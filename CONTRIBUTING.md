# Contributing

Thanks for taking the time to contribute.


## Before You Start

- Keep changes focused. One logical change per pull request.
- If you're planning a large feature or significant refactor, open an issue/discussion first to discuss it.


## Code Style

- Follow the existing style of the project.
- Prefer simple, readable code over clever code.
- Write code that explains itself. Comments should explain *why*, not *what*.


## Commits

- Make small, logical commits where practical.
- Write clear commit messages that describe the change.


## Pull Requests

Keep pull requests small and focused.

The description doesn't need to be an essay. We prefer:

- What changed
- Why it changed
- Anything reviewers should pay attention to

A few sentences are usually enough. Let the code do the talking.

Please avoid AI-generated PR descriptions filled with generic boilerplate or long checklists. Reviewers will read the code—the description should provide context, not repeat the diff.


## Testing

WE don't currently have separate tests, so just document what was done and what the result was.


## Be Respectful

Assume good intent, be constructive in reviews, and help keep discussions focused on improving the project.
